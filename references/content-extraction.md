# 文案写法 — 单页校对 · 长文写作 · 文风 · 自检

本文件是卡片文案的唯一写法依据。`SKILL.md` 只讲流程，`layout-spec.md` 只讲数值，怎么写在这里。

适用范围：

- **§1 单页校对**：单页模式。用户给的是成品，只做格式校对和超限删减，不写作。
- **§2–§4 长文写作**：长文模式。用户给大纲和事例，写成文章再压成卡。
- **§5 文风、§6 自检**：长文模式全部适用；单页模式只用 §6 里标注的几项。

## 1. 单页模式：只校对格式，不改写

用户的文字就是成品。改动边界：

| 直接改 | 不改 |
| --- | --- |
| 标点：中文语境统一全角标点、补漏掉的句号、删重复标点 | 用词、句式、语序、语气 |
| 明显错别字、的地得 | 观点和事例本身 |
| 分段：合并或拆分成 1–3 段（只在原有句子边界上切） | 不为了凑行数补任何新句子 |
| 去掉 emoji、列表符号、markdown 标记，转成连贯正文 | |

**超限直接删，删完汇报**：

- 正文超 14 行：按"重复展开 → 次要例证细节 → 铺垫句"的顺序整句删，保住主论点和用户最核心的那个
  事例，删到 ≤14 行。只删整句或整个分句，不在句子内部改字。
- 标题超 13 字宽：删修饰成分（副词、定语）压到 13 以内，不换说法。
- 用户没给标题：从正文里取最核心的判断压成一行标题，汇报时单独标明"标题是我拟的"。

**不足 6 行不补写**：告诉用户差几行，由用户补充。补写就是在替用户遣词造句。

交付时附改动清单：格式改了哪些（可以概括）、删了哪几句（逐句列原文）、标题是否为拟写。

## 2. 长文模式：从大纲到文章

用户提供大纲：主论点、各章要点、各章事例。**大纲里的章就是卡片的章，一章一张章节卡**，
不增章、不并章、不改章序。

### 2.1 总分结构

- **总**：开篇一段讲清全文的主论点，并预告接下来分几章、各讲什么。这一段之后会压成封面卡的
  标题和 intro。
- **分**：每章围绕一个分论点展开，章与章之间是支撑主论点的不同侧面，读者看完各章应该能
  自己回到主论点上。
- 不写结尾总结章——封面就是"总"，再写一遍是重复。

### 2.2 每章有理有据

每章的骨架是 **论点 → 事例 → 由事例推出的结论**：

- 论点先亮出来，不要先铺垫半天再揭晓。
- 事例用用户给的，写具体：谁、做了什么、结果怎样。事例要真的能推出论点，不是贴在旁边的装饰。
- 推理那一步要写出来——事例为什么说明了这个论点，不能让读者自己补。

**论据只用用户给的，不编造**：数据、研究、案例、人物引言都不许凭空补。某章事例不足以支撑
论点时，在文章里用 `【缺论据：……】` 标出缺什么，交给用户决定是补材料、改论点还是让我去
搜（搜到的要注明来源）。

### 2.3 写完的标准

一篇正常的文章：一个小标题一章，章内自由分段，语言连贯。**这一步不考虑卡片、不数字数、
不管行数。** 写完读一遍，问：**这篇文章我愿意直接发出去吗？** 不愿意就重写——卡片是从它
压出来的，文章立不住，卡片不可能立得住。

这条规矩来自一次返工：早期版本绕过文章直接往卡片槽位里填，还规定了每段的形状（段首加粗
总结句、每段 ≥4 行），结果段落被迫以假的总结句开头、内容不够就同义复述、段与段无法承接。
**规则约束了每一段的形状，反而挤掉了写作本身。** 所以现在约束只在整张卡层面，段落交还给写作。

## 3. 从文章到卡片：只做减法

一章压成一张章节卡，**1–3 段、合计 6–14 行**。删例证细节、删重复展开、删铺垫，**保论证
骨架**（论点 → 事例 → 结论）——不重写、不换说法、不为了填满版面补新内容。超过 14 行就继续
删，直接删到合规，删的内容在交付 md 里不用单独列，因为文章原文就在同一个文件里可对照。

**段数跟着内容走**：论点和事例一口气讲得完就是 1 段；论点、事例、结论各自有分量就分 2–3 段。
不为了凑段数拆段，也不为了显得紧凑把三层意思塞进一段。

判断标准只有一条：

> 把段间空行删掉、连起来读，是不是一段通顺的话？

是，就对了。读起来像几条 bullet，或者任意两段调换顺序都不影响理解，说明是拼凑，回文章重压。

段首可以用"但""所以""这""反过来说"这类连接词——汉语本来就靠它们接话。唯一要避免的是
**没有内容支撑的连接词**：用"更麻烦的是"开头，后面却没有比上一段更麻烦的东西。

章节卡标题：用这一章的分论点，≤13 字宽，是一句判断，不是一个名词标签（"复利"不如"复利
只奖励不中断的人"）。

## 4. 封面卡对齐总论点

- 标题写**主论点**，不是第一章的标题。2 行，每行 ≤8 字宽，断在语义接缝处。
- intro 固定 4 行：先用一两句立住主论点的张力，再做结构预告（"N 个……"或点出各章关键词）。
  **这里不给示范句——示范句会被原样抄进文案**（已经发生过一次）。
- intro 里点到的例子和关键词必须真的出现在章节卡里，不能封面讲 A、卡里讲 B。

## 5. 文风：平和克制

语气要**平和、客观、精炼流畅**——像在把一件事讲清楚，不是在带节奏。写标题和正文时避开三类写法：

1. **危言耸听**：用"最危险""致命""毁掉你的一生"这类极端词给结论镀金，把观点讲成警告。
2. **故作悬疑**：先吊胃口再公布答案（"你猜猜看""答案是……"）、刻意的"不是A，是B"反转句式。
   事例本身有分量就直接给出来，不用铺垫悬念。
3. **矫揉造作**：堆排比、堆金句、过度比喻，读起来像鸡汤文案而不是在讲一件具体的事；也包括
   为了句式工整牺牲准确性。

自检：读一遍标题，问自己"这是在讲清一件事，还是在制造情绪或悬念"——是前者才算过关。改法是
把渲染的词换成准确、克制的表达，不是删掉整句话。

单页模式不适用本节——用户的语气就是用户的，不替用户调文风。

## 6. 成稿自检清单

逐项通读，发现问题就地改，改完重新过一遍，直到清零。

**字宽、行数、段数、emoji、页码这类机器能查的约束不用在这里人工核对**——渲染前
`scripts/check-cards.mjs` 会全部拦截。这份清单只查脚本看不见的东西：

| 检查项 | 查什么 | 不过关回炉 | 单页模式 |
| --- | --- | --- | --- |
| 错别字与标点 | 错别字、的地得、中英文标点混用 | 就地改 | ✓ |
| 删减不伤原意 | 删完的句子还连得上，没有删掉被后文指代的内容 | 换一句删 | ✓ |
| 大纲对齐 | 章数、章序、各章论点和大纲一致，没有漏章或自创章 | 对照大纲 | |
| 论证完整 | 每章都有 论点 → 事例 → 结论，推理那一步写出来了 | §2.2 | |
| 论据来源 | 每个事例、数据都来自用户大纲，缺的已用 `【缺论据】` 标出 | 删掉编造的内容 | |
| 事实归因 | 事例里谁做的、谁说的，和大纲一致，没有张冠李戴 | 对照大纲 | |
| 连读通顺 | 删掉段间空行连起来读是一段通顺的话；任意两段调换顺序会影响理解 | §3 重压 | |
| 总分对应 | 各章合起来确实支撑封面主论点；封面 intro 点到的内容都在章节卡里 | §2.1 / §4 | |
| 跨章一致 | 人名、术语前后统一；不同章不重复用同一个例子、同一句话 | 全批统一 | |
| 语气文风 | 有没有危言耸听 / 故作悬疑 / 矫揉造作 | §5 换词，不改事实 | |

清零之后，回 `SKILL.md` 进入下一步。
